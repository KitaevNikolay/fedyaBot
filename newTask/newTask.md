# План доработки: авторские стили (тон-оф-войс) + запрет заголовков «Тема: расшифровка»

Сводный план по ТЗ заказчицы (`tz.md`, `ZADANIE_DLYa_ISPOLNITELYA.docx`, файлы правок 01–05)
с учётом **поздних корректировок** из файла «я бы хотела нейтрализовать яркий стиль мемрук…»:
блок Мемрук берём в нейтрализованной версии, добавляем двух новых авторов (Марина Климова, Дмитрий Морозов) — итого **7 авторов + «Без стиля»**.

Важно про терминологию: в ТЗ заказчица пишет «BotHelp», но фактически пайплайн работает
в нашем Telegram-боте (fedyaBot). Всё, что в ТЗ описано как «шаг с кнопками в BotHelp»,
реализуем в интерфейсе бота. Промпты лежат в Outline (доступ по API — только чтение:
готовим новые версии текстов, применяет владелец).

## Часть A. Правки промптов в Outline

**Ограничение: доступ к Outline — только чтение.** Менять или удалять документы по API нельзя.
Поэтому формат работы такой:

1. Текущие версии шести целевых промптов скачаны в `newTask/outline_current/` (сделано,
   коллекция «Fedya Prompts (Astral Journal)», все якорные разделы из файлов правок на месте).
2. Готовим **новые полные версии** промптов в `newTask/prompts_new/` + краткий diff-обзор
   «что изменилось» для согласования.
3. Применение в Outline — вручную владельцем (заказчицей/админом) копипастой готовых текстов,
   либо нами после выдачи write-доступа. Ничего в Outline не меняем без отдельной команды.

Целевые документы (ID в Outline):

| Промпт | Документ | ID |

| generate_article системный | Генерация статьи системный промт | `5a41495d-…a67b5` |
| generate_article пользовательский | Генерация статьи пользовательский промт | `3ed51857-…ffcfa` |

## Часть B. Доработки бота (код fedyaBot)

Ключевое отличие от ТЗ «для BotHelp»: у нас переменные подставляются кодом
(`prompt-template.helpers.ts`), а контекст пользователя в Redis **очищается после каждого шага**.
Поэтому автора нужно хранить на уровне статьи в БД — иначе шаги 5/6/9 его не увидят.

### B1. Плейсхолдер `author_name` (код + админка)
`src/modules/bothub/prompt-template.helpers.ts`:
- добавить ключ `author_name` (label «Стиль автора») в `PromptPlaceholderKey`;
- подключить его к типам: `generate_article`, `rewrite_article`, `article_uniqueness`,
  `seo_rewrite_article`.

Пустое/непереданное значение подставляется как пустая строка — поведение «Без стиля»
работает из коробки, ни один шаг не ломается.

**Отображение в админ-кабинете**: страница «Настройки генерации» рендерит плейсхолдеры
из ответа API (`GenerationSettingsPage.tsx` → `setting.placeholders`), который бэкенд
собирает из этого же реестра (`admin-generation-settings.service.ts:107`). После правки
helpers `{{ author_name }}` появится в карточках всех четырёх типов генерации
(токен + подпись «Стиль автора») без изменений фронтенда кабинета. Проверяем визуально
на этапе тестирования.

### B2. Хранение автора статьи
`prisma/schema.prisma`: колонка `authorName String?` в модели `Article` + миграция.
`ArticlesService`: метод обновления `authorName`.
Перед миграцией — бэкап БД (как описано в README).

### B3. BothubService
Методы `generateArticle`, `rewriteArticle`, `makeArticleUnique`, `seoRewriteArticle`
принимают опциональный `authorName` и передают его в `values` (`author_name`).

### B4. Выбор автора в интерфейсе бота

**Перед генерацией статьи (шаг 3).** После подтверждения вопросов (и в ветке загрузки
вопросов файлом) — перед запуском `generate_article` показываем клавиатуру выбора автора,
новое состояние `WAITING_FOR_AUTHOR_SELECTION`, callback вида `author_select:<код>`.
Выбор пишем в Redis-контекст и в `Article.authorName`, затем запускаем генерацию.

Кнопки (по одной в ряд, тексты — в `config/locales/ru.json`, callback-ключи — в
`config/constants/bot.json`):

- Евгения Мемрук (отчётность, налоги — сдержанный тон)
- Марина Климова (отчётность — сухой методологический тон)
- Дмитрий Морозов (ЭДО/ЭПД — технический тон)
- Оксана Каверина (ЭДО, малый бизнес — практический тон)
- Алексей Иванов (финансы, объяснение сложного)
- Марат Самитов (бизнес, налоги, риски)
- Надежда Самкова (законы, закупки, норма)
- Без стиля автора

(подсказки для Климовой/Морозова/Мемрук/Кавериной — из поздней правки 4,
для остальных — из первоначального списка в tz.md; «Без стиля» → authorName пустой)

**rewrite_article и article_uniqueness** — без вопросов пользователю: автор читается
из `Article.authorName` автоматически (сценарий А из ТЗ).

**SEO-шаг (сценарий Б — апдейт старого текста).** Перед запросом SEO-ТЗ — необязательный
вопрос «Хотите применить авторский стиль?» с теми же кнопками. Если у статьи уже есть
`authorName` — первой кнопкой «Оставить текущего: <имя>». Выбор сохраняем в
`Article.authorName` (чтобы последующие шаги были консистентны).

## Часть C. Что сознательно НЕ делаем

- **Автоматическую ротацию авторов по рубрикам** (матрица «Отчётность: Мемрук ⇄ Климова»,
  «ЭДО: Каверина ⇄ Морозов» из правки 5) — не автоматизируем. Выбор остаётся за редактором,
  подсказки зашиты в кнопки; шпаргалку по рубрикам заказчица раздаёт авторам сама
  («это отдельно от твоей работы»).
- Не копируем блоки авторов в другие промты — они живут только в системном промте
  `generate_article`, остальные шаги ссылаются на раздел (по ТЗ, во избежание рассинхрона).
