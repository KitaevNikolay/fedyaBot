# API

## Бот в Яндекс Мессенджере

- Любое первое сообщение боту регистрирует пользователя (кнопки «Start» в Яндексе нет); текст вне сценария показывает главное меню.
- Команда `/start` (набирается текстом) создает сессию и запускает сценарий.
- Команда `/cancel` сбрасывает текущее состояние, `/menu` открывает меню работы со статьей.
- Кнопки под сообщениями — `suggest_buttons` с директивой `server_action`; нажатие приходит боту как `bot_request` и не публикует сообщение в чат.
- **Roadmap**: В сообщениях отображается следующий ожидаемый шаг (Генерация статьи -> Факт-чек -> Продукты).
- Генерация факт-чека и переписывание статьи происходят автоматически с сохранением результата.
- SEO‑оптимизация запускается после факт-чека через загрузку ТЗ в формате .docx.
- Кнопки генерации продуктов и рубрик появляются только после завершения факт-чека.
- Поддерживается загрузка `.docx` файлов для контекста.
- Админ-меню доступно только пользователям с role=admin.
- Сообщения о рубриках и продуктах краткие, без дублирования контента.
- Ошибки генерации логируются в файл с типом generation_error.
- В Users сохраняются messengerId (логин Яндекса), username, firstName, lastName.
- В логах Bothub фиксируются плейсхолдеры, используемые в system/user промптах.

## Вход в кабинет (cabinet-api)

- `POST /admin/auth/request-code` `{ login }` — бот отправляет одноразовый 6-значный код в личный чат пользователя (код живёт 5 минут, повторный запрос не чаще раза в 30 секунд).
- `POST /admin/auth/verify-code` `{ login, code }` — проверка кода; пользователь создаётся (неактивным), а логины из `CABINET_ADMIN_LOGINS` сразу получают роль admin. Ответ: `{ user, status: approved | pending | forbidden, accessToken }`.
- `GET /admin/auth/me` — текущий администратор по Bearer-токену сессии.

## Внутренние настройки генерации

- Настройки генерации и промпты управляются через БД и Outline
- Отдельных HTTP эндпоинтов пока нет
