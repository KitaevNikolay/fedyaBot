### Модуль Bot

Содержит логику обработки команд и кнопок Яндекс Мессенджера поверх модуля **Messenger**
(`src/modules/messenger`): `YandexMessengerApiService` — HTTP-клиент Bot API (sendText, sendFile,
getFile, getUpdates, self/update), `MessengerBot` — маршрутизатор обновлений (команды, callback-кнопки,
текст, документы; очередь на чат, параллельно между чатами), `MessengerContext` — контекст ответа
(reply/replyWithDocument с разбиением текста по лимиту 6000 символов), `InlineKeyboard` — построитель
`suggest_buttons`. Обновления приходят через polling (`getUpdates`) или webhook (`YANDEX_WEBHOOK_URL`,
маршрут регистрируется в `main.ts` и отвечает Яндексу сразу, обработка идёт в фоне).
Включает в себя:
- **Middleware дедупликации**: Проверка `update_id` через Redis (`SET NX`) для предотвращения повторной обработки (вебхук Яндекса доставляет «at least once»).
- Обработку сценариев
- Меню работы со статьями
- Загрузку вопросов, факт-чека и SEO‑ТЗ из .docx файлов
- Отмену ввода через /cancel с возвратом в меню статьи
- Меню администратора (для роли admin)
- Логирование действий через `AppLoggerService` в файлы на хосте.

### Безопасность

- **Webhooks Security**: Проверка входящих запросов по секретному токену (рекомендуется в будущем).
- **AdminGuard**: Guard для проверки роли администратора (в common/guards).
- Проверка админ-доступа основана на поле role у пользователя.
- Валидация входных данных через DTO и Pipes.

## Хранение данных

- **MySQL**: Основная БД (пользователи с логином Яндекса, сессии, статьи, дополнения, настройки генерации).
- **Redis**: Хранение временных состояний бота, контекста генерации и **замков дедупликации** (TTL 1 минута для замков, 3 часа для сессий).
- **Outline**: Хранилище промптов (system/user) с доступом по ID.
- **Логи**: Файловое логирование пользовательских действий, внешних запросов и ошибок генерации. Логи монтируются из контейнера в папку `./logs` на хосте.
- **Bothub логирование**: Для внешних запросов логируются используемые плейсхолдеры system/user промптов.
